Architecture for browser-based age encryption with passwordless authentication. I’ll structure it so you can visualize the client-side encryption workflow, optional server/storage components, and interoperability with CLI tools.

use case:

Browser-native and lightweight.

Implements WebAuthn PRF for hardware keys and passkeys.

Fully interoperable with Go age + plugin ecosystem.

Avoid managing cross-language bindings.

🔹 Workflow Description

Client Key Generation

User opens your web app.

typage-encryption generates an Age identity (X25519 keypair).

User selects authentication method:

Passkey (WebAuthn discoverable credential)

Hardware key (YubiKey / non-discoverable FIDO2)

TPM / biometric (via platform authenticator)

File Encryption

File is encrypted entirely in the browser.

Symmetric key is wrapped using the selected identity.

Optional ASCII armor for easy transport.

File Storage / Sharing

Encrypted file can be uploaded to a cloud, NAS, or P2P sharing service.

No plaintext or secret leaves the client.

Recipient Access

Recipient uses your app or CLI:

Browser: typage-encryption + WebAuthn (same site origin ensures PRF compatibility)

CLI: Go age-plugin-fido2prf if they have a hardware key

Decrypts file locally using their credential.

Interoperability

Files encrypted in-browser can be decrypted in Go CLI (and vice-versa) using the FIDO2 plugin.

Optional: integrate with identity providers to simplify user onboarding while maintaining passwordless auth.

🔹 Key Advantages of This Architecture

Security: Encryption and decryption happen entirely locally; no secrets leave the browser.

Passwordless auth: WebAuthn / FIDO2 integration covers passkeys, YubiKeys, TPM, biometrics.

Interoperability: Browser files can be shared and decrypted via CLI tools (Go + plugin) for advanced users.

Scalable file sharing: Works with any cloud storage, file servers, or even peer-to-peer solutions.

Future-proof: Adding new authentication methods (like new WebAuthn capabilities) doesn’t break core encryption.
